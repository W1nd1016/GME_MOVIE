## 2026-11-28 · 0.1 数据产物与底座训练入口

六种用途各存一份样本 NPZ，物品属性和邻居电影 ID 单独写入 `items.npz`。这样 GME 基线可以从物品表查邻居，最终评分样本只向评分用途开放。原 `base_candidate` 覆盖元训练电影，0.1 通过内部生成的合成样本验证训练入口，0.4 验证物品级留出后再接入真实底座训练数据。[数据接口](ARCHITECTURE.md#31-数据用途split)

## 0.4 物品划分与底座复用

2026-11-29 确认，适用于阶段 0 的 MovieLens 实验。0.4 负责物品划分和底座预训练，0.6 的 GME 基线使用以下邻居规则。

| 事项 | 决定 | 理由 |
|---|---|---|
| 老电影如何留出 | 将 1058 部老电影按 9:1 划为 952 部底座电影和 106 部伪新电影。用固定划分种子按电影 ID 随机分组一次，保存两组 ID 清单，所有方法和训练种子复用。底座只用底座组的交互，元训练 A/B 只用伪新组的交互，两组与 1127 部测试电影两两互斥。 | 加工数据缺少时间戳。按电影留出能保证底座训练时从未见过伪新电影的交互。9:1 让大部分老电影用于底座预训练，同时为元训练单独留出 106 部电影。 |
| GME 可借哪些邻居的 ID 向量 | 保留物品表中的原始邻居名单。需要邻居 ID 向量时，只取底座组邻居。若一个也没有，用目标电影自身属性生成初始向量。0.4 在划分后统计落入伪新组的邻居占比，以及每部目标电影剩余的可用邻居数。 | 伪新电影虽有 ID 槽位，其向量却没有从该电影的交互中学到偏好。仅借用经过底座训练的向量，才能把这部分信号解释为邻居的协同信息。原始选邻规则及其上架时可用性仍未核实。 |
| 各方法怎样共用底座 | 0.4 用底座组交互训练并保存一份 CTR 底座 checkpoint，同时记录配置和对应的物品划分。阶段 0 的各冷启动方法加载并冻结同一份权重，将各自生成或适配的目标电影向量送入底座评分。 | 即使 DNN 结构相同，各方法分别预训练也会引入权重差异。固定评分模型后，在相同划分和预算下比较，才能判断电影向量的生成或适配方式带来了什么差异。 |

同日批准的实施计划将划分种子固定为 `42`。先对老电影 ID 去重排序，再用 PCG64 打乱，取前 106 部作为伪新电影。清单中的三个 ID 列表按升序保存。后续方法按清单过滤原始 NPZ，保持同源样本的行序，也避免额外复制三份交互数据。[实施计划](plans/0.4-item-holdout.md)

底座使用独立训练种子 `123`，在 CPU 上以 Adam、学习率 `0.001`、批量 `128` 遍历全部底座交互一次，保留尾批并保存末步权重。固定预算沿用旧底座设置，选择 checkpoint 时无需读取任何冷启动反馈。运行目录保存实际使用的划分清单和 SHA-256，便于核对实验共用的底座和电影分组。[旧底座配置](../config_dnn.py)

## 0.2 元训练电影数量与验证

2026-11-29 确认，阶段 0 先沿用 0.4 的 9:1 划分和冻结底座。伪新电影从旧数据池的 1058 部减至 106 部，每部仍有 20 条 A 和 20 条 B。增加训练轮数可以补足生成器的更新次数。要判断增加独立电影是否有益，还需在生成器训练时留出整部电影。[0.2 训练配置](../configs/meta_training.yaml) · [实验登记表](EXPERIMENTS.md)

- **按电影验证。** 在 106 部伪新电影中固定 85 部用于元训练、21 部用于元验证。每部电影的 A/B 始终同组。验证时只用 A 适配该电影的临时向量并构造可见历史，在 B 上计算 query logloss。共享生成器的梯度更新只来自训练电影。最终测试集继续专用于评分。
- **检查训练预算。** 从最小属性生成器开始，每次外层更新取 4 部电影，保留尾批，85 部电影每轮更新 22 次。在第 1、5、10、20 轮比较训练与验证电影的 query logloss。对照组使用一个共用初始向量，执行相同适配。训练与验证损失仍同步下降时可延长训练。如果生成器在训练电影上的损失也难以低于对照组，先检查 B 的梯度与 A 适配前后电影向量的变化。训练损失继续下降而验证变差时，依据元验证集早停。
- **检查电影数量。** 从 85 部训练电影中取彼此嵌套的 25、50、85 部，固定底座、21 部验证电影和外层更新步数。按至少 3 个训练种子比较验证 query logloss 的均值与波动。若验证表现随电影数增加而持续改善，再单独评估 8:2。届时用 846 部底座电影重新预训练，212 部伪新电影中保留原 21 部验证电影，在同一份新底座上比较 85 部与 191 部训练电影。这样可以区分增加元任务数的收益与更换底座的影响。

## 0.5 测试电影的反馈到达批次

2026-11-29 确认。测试侧 B 每部电影有 20 条反馈，加工数据缺少交互时间。按电影对（电影 ID，用户 ID）计算带固定版本前缀的 SHA-256，再按摘要顺序各取 10 条。这样，文件行序、交互标签和训练种子都不会改变每位用户出现的轮次。所有方法共用同一次划分。[固定分组规则](plans/0.5-warm-arrivals.md#划分与产物)

原始 A/B 都能以更新用途整份读取，容易在第二轮提前看到 B 的后 10 条。三个新增批次因此各存一份 NPZ，原始 A/B 的访问用途收紧为 `partition`。逐轮更新时只打开当轮文件，相同的样本格式可以沿用现有 Dataset。最终集交互键只在独立验收中用于核对互斥，生成批次只依赖 A/B 和 0.4 的测试电影清单。

## 2026-11-29 · 0.2 电影向量与元训练诊断

| 需要决定的问题 | 选择与理由 |
|---|---|
| 冻结底座后如何对新电影评分并训练生成器 | 扩展 `BaseDNN.forward`，允许调用者传入每行的电影向量。各方法共用已训练的 MLP 和其余特征槽，评分梯度可以传给生成器。临时向量只属于当前电影任务，后续电影和基线仍能载入同一份 0.4 权重。 |
| 梯度适配与 B 损失如何配合 | 每部电影的 20 条 A 交互共用一个初值，对本片平均 BCE 做一步适配，步长为 0.1。多片合批时先逐片取平均，再对各片损失之和求各自的向量梯度，以免尾批改变有效步长。外层以训练电影的 B 单独计损失，通过完整的一步 MAML 梯度训练共享参数。这样 B 梯度直接衡量适配后预测另一批用户的能力。旧审查举例的 A/B 加权损失还会直接奖励 A 上的拟合程度。 |
| 怎样校准，又能区分属性本身带来的收益 | 校准只取 A 中正反馈用户向量的均值，加到适配向量的残差为均值的无偏置线性投影。按实际人数取均值让少量正反馈保有正常尺度，无正反馈时保留完整的 A 梯度适配结果。属性组从 year、title、genres 生成初值，对照组学习一个共享初值。两组的冷初值、初始校准增量均为零，使用同结构校准层与同一内层步长。 |
| 不同电影数怎样公平比较 | 用固定种子 2026 置换排序后的 106 个电影 ID，前 21 部用于验证，其余 85 部名单的前缀构成训练子集。每轮给各组 85 个电影任务，小组循环使用该轮随机排列，使三组在 440 次更新中都累计 1700 部次。电影数主比较取同一步的验证损失。为后续复用的权重另取四个检查点中验证损失最低者，并列取最早。这既能比较固定预算，也能在验证变差时保留较早的权重。 |

上述决定适用于阶段 0 的最小生成器和元训练诊断。0.3 可以复用可见历史和冻结底座的评分接口，测试电影的逐轮更新协议由 0.3 验收。[实施计划](plans/0.2-meta-training.md) · [元训练接口](ARCHITECTURE.md#36-伪新电影的元训练与验证)
