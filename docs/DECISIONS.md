以下决定已由用户确认。[开发规则](../AGENTS.md) · [阶段 0 路线图](../ROADMAP.md)

| 事项 | 决定 | 备选方案与取舍理由 |
|---|---|---|
| 开发与训练环境 | 在当前 VS Code 连接的 WSL2 Ubuntu 上完成开发、测试、正式训练和评测，按单张 RTX 4090 预算设计。 | 原方案在 Mac 开发、另机训练，再回传结果。当前 WSL 可以统一执行并直接核对本机产物。 |
| 阶段 0 的到达顺序 | 使用仓库内已加工的 MovieLens-1M。交互缺少时间戳，用互斥批次模拟反馈到达，后一批在前一批用完后才开放。 | 重建真实时间线需要额外取得带时间戳的原始数据并恢复映射。现有数据足以检验各测点的信息可见性。阶段 2 将在带时间戳的主实验数据上按实际事件时间回放。 |
| 三轮 warm-up 与评估集 | 每部新电影先开放测试侧 A 的 20 条，再依次开放测试侧 B 的两组各 10 条。B 按电影固定划分，与标签无关，所有方法和训练种子共用。三批与完整的 `test_test_w_ngb_hist.tfrecord` 按（用户，电影）两两互斥。四个测点在该集合上评估累计 0、20、30、40 条交互的效果。 | 旧 A/B 方案只能观察两轮。拆分 B 可增加一个观测点，同时保留全部 1127 部新电影、原有的 20/40 条测点和 123,787 条最终评估样本。 |
| 历史反馈的可见范围 | cold 时目标电影的 `hist` 为空。每轮更新后仅从该电影累计已开放的正反馈重建 `hist`。元训练若采用 A→B，只用 support A 的正反馈校准适配后的 embedding，再在 query B 评分。最终评估数据仅用于评分，标签及其派生信息不得用于生成或更新 embedding、训练或早停。 | 直接使用旧文件附带的 `hist` 会把当前或最终评估批次的正反馈用户提前暴露给模型。具体证据见[旧代码审查](../CODE_REVIEW.md)。 |

## 2026-11-28 · 阶段 0 泄漏修复的验收

取消用旧 `hist` 重跑以量化指标偏差的对照实验。该实验只能估计旧协议对指标的影响。新协议通过 0.2、0.3 的测试验证历史反馈的可见范围，0.6 的基线按新协议比较。[阶段 0 交付物](../ROADMAP.md#13-交付物)

## 2026-11-28 · 0.1 数据产物与底座训练入口

六种用途各存一份样本 NPZ，物品属性和邻居电影 ID 单独写入 `items.npz`。这样 GME 基线可以从物品表查邻居，最终评分样本只向评分用途开放。原 `base_candidate` 覆盖元训练电影，0.1 通过内部生成的合成样本验证训练入口，0.4 验证物品级留出后再接入真实底座训练数据。[数据接口](ARCHITECTURE.md#31-数据用途split)

## 0.4 物品划分与底座复用

2026-11-29 确认，适用于阶段 0 的 MovieLens 实验。划分和底座预训练待 0.4 执行，GME 基线在 0.6 使用以下邻居规则。

| 事项 | 决定 | 理由 |
|---|---|---|
| 老电影如何留出 | 将 1058 部老电影按 9:1 划为 952 部底座电影和 106 部伪新电影。用固定划分种子按电影 ID 随机分组一次，保存两组 ID 清单，所有方法和训练种子复用。底座只用底座组的交互，元训练 A/B 只用伪新组的交互，两组与 1127 部测试电影两两互斥。 | 加工数据缺少时间戳。按电影留出能保证底座训练时从未见过伪新电影的交互。9:1 让大部分老电影用于底座预训练，同时为元训练单独留出 106 部电影。 |
| GME 可借哪些邻居的 ID 向量 | 保留物品表中的原始邻居名单。需要邻居 ID 向量时，只取底座组邻居。若一个也没有，用目标电影自身属性生成初始向量。0.4 在划分后统计落入伪新组的邻居占比，以及每部目标电影剩余的可用邻居数。 | 伪新电影虽有 ID 槽位，其向量却没有从该电影的交互中学到偏好。仅借用经过底座训练的向量，才能把这部分信号解释为邻居的协同信息。原始选邻规则及其上架时可用性仍未核实。 |
| 各方法怎样共用底座 | 0.4 用底座组交互训练并保存一份 CTR 底座 checkpoint，同时记录配置和对应的物品划分。阶段 0 的各冷启动方法加载并冻结同一份权重，将各自生成或适配的目标电影向量送入底座评分。 | 即使 DNN 结构相同，各方法分别预训练也会引入权重差异。固定评分模型后，在相同划分和预算下比较，才能判断电影向量的生成或适配方式带来了什么差异。 |

同日批准的实施计划将划分种子固定为 `42`。先对老电影 ID 去重排序，再用 PCG64 打乱，取前 106 部作为伪新电影。清单中的三个 ID 列表按升序保存。后续方法按清单过滤原始 NPZ，保持同源样本的行序，也避免额外复制三份交互数据。[实施计划](plans/0.4-item-holdout.md)

底座使用独立训练种子 `123`，在 CPU 上以 Adam、学习率 `0.001`、批量 `128` 遍历全部底座交互一次，保留尾批并保存末步权重。固定预算沿用旧底座设置，选择 checkpoint 时无需读取任何冷启动反馈。运行目录保存实际使用的划分清单和 SHA-256，便于核对实验共用的底座和电影分组。[旧底座配置](../config_dnn.py)
