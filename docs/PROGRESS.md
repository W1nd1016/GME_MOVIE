先做 0.4 和 0.5，训练端与评测端就能使用同一份已经核验的划分。0.4 已确认[物品划分、GME 邻居使用规则和底座复用方式](DECISIONS.md#04-物品划分与底座复用)。先做 0.7 再跑 0.6，可以在比较模型之前用已知答案查出指标实现错误。0.7 验收指标代码和汇总工具，0.6 产出正式的模型对比表。阶段 0 验收时核对 0.2、0.3 的标签可见性测试结果及各基线的四个测点曲线。

0.6 使用邻居 ID 向量时，可用数由[邻居覆盖统计](../artifacts/holdouts/0.4/neighbors.json)查得。伪新组有 105 / 1060 个邻居位置指向伪新电影，测试组有 1195 / 11,270 个。每部伪新电影至少保留 6 个可用位置，每部测试电影至少保留 5 个。原始选邻规则及其上架时可用性仍未核实。阶段 0 完成时补充 GME 基线的实际用法。

## 每个任务怎样推进

1. 从上表选取一个任务号。读取对应路线条目和上一项验收记录，查清本项输入、依赖和遗留问题。
2. 在 `docs/plans/` 写本项计划，列出文件范围、设计、风险和可验证的完成条件，提交用户审批。
3. 获批后从 `main` 建任务分支，先写测试再实现。在本机运行测试、冒烟检查和计划内的实验。
4. 用验收结果更新本表，包括实际分支、完成日期、结果和遗留问题。有真实指标时登记实验，提交前按[开发规则](../AGENTS.md)核对决策记录。将实现、测试和记录一起提交到任务分支。需要合并时征得用户同意，使后续分支能取得前置任务的代码。

阶段 0 验收后，按路线图迁移到 MicroLens 并重跑基线，再依次推进语义 ID、流式 warm-up 和可选的 LLM 增强。进入各阶段时，根据前一阶段产物细化下一项任务计划。
