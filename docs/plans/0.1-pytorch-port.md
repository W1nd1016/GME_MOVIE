# 任务 0.1 · MovieLens 数据转换与 PyTorch 底座

**待用户审批。** 候选分支为 `feat/0.1-pytorch-port`。以下文件、命令和验收条件均为提案，尚未实施或运行。

## 目标与交付

把现有 MovieLens 数据转成按用途存放的 NPZ，用 PyTorch 的 Dataset 和 DataLoader 读取，在当前 WSL2 Ubuntu 上用固定种子完成一次可重复的 CPU 训练冒烟。模型结构以旧底座为参照。[路线图任务 0.1](../../ROADMAP.md) · [旧底座](../../base_dnn.py)

| 拟新增或更新的文件 | 用途 |
|---|---|
| `scripts/convert_movielens.py` | 在已有 `gme_movie_tf1` 环境中逐条读取 TFRecord，输出 NPZ 和含源文件、用途、行数的清单 |
| `src/coldstart/data/movielens.py`、`src/coldstart/models/base_dnn.py` | 加载具名数组，按槽位汇总特征并输出每条交互的 logit |
| `scripts/train_base.py`、`configs/base_smoke.yaml` | 配置数据、随机种子与训练步数，运行冒烟并保存权重和运行记录 |
| `pyproject.toml`、`.gitignore` | 声明新包与测试依赖，忽略派生数据 `artifacts/`、训练输出 `runs/` 和本地环境 |
| `tests/test_movielens.py`、`tests/test_base_dnn.py`、`tests/test_train_base.py` | 验证转换、前向计算、数据用途和训练复现性 |

任务验收后更新 [进度表](../PROGRESS.md)。需要安装的新依赖将在实施前说明。

## 数据与训练设计

1. 为底座源数据、元训练 A/B、预热 A/B 和最终评估分别输出文件，共六份。每种用途只转换一份 TFRecord，避免把同源 CSV 或重复的 `test_oneshot_a` 计入两次。没有 CSV 的 `data_with_hist/test_test_w_ngb_hist.tfrecord` 直接转换。保留每个源内的行序，批次顺序的含义由任务 0.5 定义。
2. 每条记录拆成二值标签、当前样本的 16 个特征 ID 和可选的 `10 × 16` 邻居特征，保留 ID 编码及零填充。旧 `hist` 含标签派生信息，从输出中剔除。标签独立存放，底座前向只接收当前样本特征。最终评估数据单独标记，训练入口拒绝接收该用途。
3. 对齐旧底座的共享 `11135 × 10` embedding。6 个单值槽位直接查表，标题和类型各自对 5 个位置做掩码求和，拼成 80 维输入。沿用无偏置的 `80 → 256 → 128 → 1` 网络、隐藏层 ReLU、交叉熵与 Adam。固定 Python、NumPy、PyTorch 与训练抽样的种子，同一 CPU 环境比较结果。
4. 冒烟配置使用按上述格式生成的小型合成交互走完整的加载、训练和权重重载流程。原始 `big_train_main` 包含元训练物品，其转换产物标记为候选数据。训练入口仅接受合成冒烟数据或已做物品级留出的训练数据，实际 MovieLens 底座训练须使用任务 0.4 的划分。

## 拟执行的验收

计划在仓库根目录执行。第一条使用旧环境，其余命令使用已安装本项目和测试依赖的 PyTorch 环境。

```bash
conda run -n gme_movie_tf1 python scripts/convert_movielens.py --output artifacts/movielens
python -m pytest -q tests/test_movielens.py tests/test_base_dnn.py tests/test_train_base.py
python scripts/train_base.py --config configs/base_smoke.yaml --run-dir runs/0.1-smoke
```

| 具体验收 | 通过条件 |
|---|---|
| `test_conversion_preserves_rows_and_fields` | 对照可读 CSV 核对标签与当前特征，保留可用邻居。完整转换的六份记录数依次为 765,669、21,160、21,160、22,540、22,540、123,787。最终集的末条及不足一个 batch 的尾批均可读取 |
| `test_legacy_hist_is_excluded`、`test_train_rejects_ineligible_splits` | 改变输入样例的旧 hist 后，转换得到的建模数组不变。尝试将最终集或未做物品留出的候选数据传给训练入口会在更新前报错 |
| `test_base_dnn_slot_pooling_and_logits` | 给定人工权重与一条含 padding 的样例，可逐槽核对求和与 logit。输出每条交互一个有限值 |
| `test_seeded_smoke_and_checkpoint_reload` | 同环境同种子运行两次，批次顺序、逐步 loss 与最终权重一致。至少一个权重发生更新，重新载入后同一样例的预测一致 |

冒烟目录须包含本次配置、git commit、种子、权重及记录训练步数和 loss 的 `metrics.json`。这些数值用于确认训练链路可用。

## 风险、后续边界与面试要点

任务 0.2、0.3 分别实现训练侧和测试侧的历史重建。0.4 决定预训练和伪新物品划分。0.5 生成互斥的三轮预热批次。0.6、0.7 运行基线并报告四个测点的 AUC、GAUC 和 logloss。任务 0.1 的验收依据是数据完整性、模型计算及训练复现性。

面试时可以结合数据行数检查与字段隔离测试，解释只读 CSV 为什么会丢掉整份最终评估集，以及把旧记录的所有字段直接喂给模型怎样重新引入 `hist` 泄漏。
