# 任务 0.2 · 用一部电影的早期反馈学习怎样给新电影评分

一部电影刚上架时，CTR 模型已经认识用户和电影属性，但这部电影的 ID 向量还没有从交互中学到偏好。项目最终希望用内容与语义 ID 提供初值，再用早期反馈调整它。阶段 0 先在 MovieLens 上回答一个更具体的问题：给定电影的属性和前 20 条反馈，能否训练一个生成器，让同一部电影对下一批用户的预测更准？0.4 留出整部电影并训练了固定的 CTR 底座，0.2 用其中的 106 部伪新电影学习和验证这件事。[阶段 0 路线](../../ROADMAP.md) · [物品级留出](0.4-item-holdout.md)

## 验证电影 576 的一次预测

按划分种子 2026 生成的验证名单中，第一部电影是 `576`。它的 A 和 B 各有 20 条交互，每批各有 20 个不同用户，两批的用户交集为空。对这一部电影，数据加载器分别给出 A、B 的整型特征矩阵 `[20,16]` 和浮点标签 `[20]`。电影 ID 负责从物品表取得静态属性，并把属于它的两批交互配成一项任务。[电影任务接口](../../src/coldstart/data/meta_tasks.py) · [数据表](../../artifacts/movielens/items.npz)

| 时点 | 电影 576 的可见信息 | 代码产生什么 |
|---|---|---|
| 上架 | 年份 ID 为 `11131`，标题槽为 `[4202,3520,0,0,0]`，类型槽为 `[21,10,0,0,0]`。这些数是共享词表里的 ID。 | 将 11 个 ID 查表，显式掩掉填充位，对每个槽分别求和，得到 3 个 10 维向量。属性生成器把拼接后的 `[1,30]` 映射为初值 `r`，形状为 `[1,10]`。 |
| 预测 A，再开放 A 的反馈 | A 中每位用户的交互特征，以及该片共同的 `r`。先产生 20 个 logits，然后读取 20 个 A 标签计算平均二元交叉熵。 | 对 `r` 求 A 损失的梯度，以步长 0.1 更新一次，得到 `r′`。A 中的正、负样本都参与这一步。 |
| 用已经开放的 A 校准 | A 中有 15 位正反馈用户，包括 `5144` 和 `10950`。 | 取这 15 位用户在冻结底座中的向量，按实际人数 15 求均值 `h_A`，得到 `r″ = r′ + W_h h_A`。若某部电影在 A 中全为负反馈，历史向量为零，无偏置校准层会原样保留 `r′`。 |
| 预测 B，再计算验证损失 | B 的 20 行交互各自提供用户等特征，共用一个 `r″`。 | 底座以 `[20,10]` 的外部向量替换各行的电影槽，拼接 8 个槽得到 `[20,80]`，经 MLP 产生 20 个 logits。此时才把 B 的标签交给 `query_loss`。电影 576 的结果参与验证检查点选择。 |

加载真实 0.4 底座和属性组（85 部、种子 123）选中的第 220 步权重，电影 576 的冷初值 L2 范数为 **0.05824**，A 上一步适配的向量变化量为 **0.04442**，正反馈校准又带来 **0.02713** 的变化量。单独翻转这部电影的 20 个 B 标签，再用同一组权重评分，初值、适配值、历史均值、校准值和 20 个 B logits 逐值相等。用原标签算出的 query logloss 为 **0.68868**，用翻转后的标签计算为 **0.86456**。同一批预测可以得到不同损失，因为 B 标签参与了评分后的核对。[生成与校准](../../src/coldstart/models/generators/attribute.py) · [A 适配与 B 评分](../../src/coldstart/train/meta.py) · [电影名单](../../runs/0.2-attribute-n85-s123/movies.json) · [实测检查点](../../runs/0.2-attribute-n85-s123/metrics.json)

## 损失怎样更新生成器

换成训练名单上的电影时，A 的作用相同。每个外层批次取至多 4 部电影，先分别对每部的 20 条 A 损失取平均，再对各电影的平均损失求和，对各自的电影向量求梯度。这样，同一部电影单独在尾批出现和与另三部合批时，内层适配步长相同。适配过程中保留梯度图，B 的损失对属性生成器的导数会经过 A 的梯度步骤。这就是这里使用的一步 MAML。[评分与求导](../../src/coldstart/train/meta.py)

外层训练将各电影的 B 损失取平均，用 Adam 更新属性生成器和正反馈校准层。底座的权重固定，MLP 对输入电影向量仍有导数，因此生成器能学到什么样的向量适合这个底座。底座的共享 embedding 表始终保留 0.4 的权重，临时电影向量只用于当次评分。验证电影同样需要在 A 上求梯度来适配临时向量，但它的 B 损失只用于衡量泛化及选择检查点。[底座的外部电影槽](../../src/coldstart/models/base_dnn.py) · [训练与验证入口](../../scripts/train_meta.py)

检查泄漏时，必须把**同一次预测**和**评分之后的学习**区分开。固定权重翻转 B 标签，本次预测的初值、适配值、历史均值、校准值和 logits 都应相同。对训练电影，评分后的 B 损失可以随标签改变，也应当能更新共享参数。测试还用数值差分核对穿过内层适配的梯度，对比单片与合批适配，以及训练电影、验证电影各自能影响哪些参数。这些检查能回答为什么“底座冻结”和“生成器仍可学习”可以同时成立。[元训练测试](../../tests/test_meta_training.py) · [评分接口测试](../../tests/test_base_dnn.py)

## 怎样解读四组训练结果

每组用 123、456、789 三个训练种子，各做 440 次外层更新、处理 1700 个电影任务。电影数较少的组会更多次重复同一批电影。下表在固定的第 440 步、同一批 21 部验证电影上比较 B 的 query logloss，数值越低越好，报告三种子的均值 ± 样本标准差。[实验登记表](../EXPERIMENTS.md) · [预算配置](../../configs/meta_training.yaml)

| 冷初值来源 | 不同训练电影数 | 元验证 query logloss |
|---|---:|---:|
| 属性生成器 | 25 | 0.599123 ± 0.000533 |
| 属性生成器 | 50 | 0.590225 ± 0.000550 |
| 属性生成器 | 85 | 0.584874 ± 0.000278 |
| 全部电影共用一个可学习初值 | 85 | 0.575432 ± 0.000145 |

**同预算下，属性组的独立电影越多，这次留出验证的损失越低。** 25 部组从第 22 步到第 440 步，平均训练损失从 0.604366 降到 0.572270，验证损失却从 0.583454 升到 0.599123。更多次重复同一小组电影可以继续改善训练拟合，同时也会加大过拟合。85 部属性组在三个种子上分别选择了第 220、110、110 步。增加伪新电影比例意味着底座电影也会减少，评估 8:2 需要单独重训底座并控制比较条件。[同预算电影数实验](../EXPERIMENTS.md) · [8:2 对照约定](../DECISIONS.md#02-元训练电影数量与验证)

**在 85 部训练电影上，共享初值对照的验证表现更好。** 它与属性组使用同一底座、电影批次和 A 适配校准过程，三个种子都选中第 440 步。当前属性生成器在相同训练预算下没有取得跨电影验证优势。三种子的波动衡量的是固定验证名单上训练顺序带来的变化，换一批验证电影仍需重新检验。单独核对 12 份选中权重时，每份都复现了 21 部验证电影的检查点损失；翻转 420 条 B 标签后，每份模型当前的电影表示和 logits 均逐值相等。协议检查与模型优劣各自有独立的验收证据。[实验登记表](../EXPERIMENTS.md) · [训练侧可见性测试](../../tests/test_meta_training.py)
