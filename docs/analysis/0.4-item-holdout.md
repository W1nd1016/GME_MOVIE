# 任务 0.4 · 为什么要从底座训练中留出整部电影

项目要预测用户对刚上架电影给出正反馈的概率。冷启动方法负责生成电影向量，CTR 底座把它与用户、电影属性一起转换为分数。阶段 0 在 MovieLens 上模拟只给上架属性、再逐批开放反馈的过程，比较各方法在同一批新电影上的预测。要模拟第一次上架，生成器练习用的电影也必须在底座预训练时留出。**0.4 交付了一份按电影 ID 固定的划分，以及只用底座组交互训练的公共评分模型。** 后续方法可以共用同一组权重，分别研究电影向量如何生成和更新。[阶段 0 路线](../../ROADMAP.md) · [预训练配置](../../configs/base_holdout.yaml)

## 跟一部电影走过三个数据入口

电影 `1593` 在底座候选池里有 **475 条**交互，在元训练 A、B 中各有 **20 条**。假如只从底座训练中删除 A、B 的 40 条交互，剩下的记录仍会通过反向传播更新电影 1593 的 ID 向量。即使元训练时重新生成该向量，底座参数也已经用过这部电影的反馈。按电影留出能消除这条路径。[源文件与行数清单](../../artifacts/movielens/manifest.json) · [旧数据重叠核查](../../CODE_REVIEW.md)

划分脚本核对候选集和 A、B 各自覆盖同样的 1058 部老电影，把去重后已排序的电影 ID 用 PCG64 和种子 `42` 打乱。前 106 部作为伪新组，其余 952 部作为底座组。物品表中另外 1127 部构成测试组。1593 落入伪新组，各训练种子复用这次分组。每次正式读取时，Dataset 用当前源文件的电影 ID、物品表及清单中的种子复核分组，通过后才按源行序筛选。[划分入口](../../scripts/prepare_holdout.py) · [划分和校验算法](../../src/coldstart/data/splits.py) · [Dataset](../../src/coldstart/data/movielens.py)

| 正式入口 | 物理输入，均位于 `artifacts/movielens/` | 实际返回 | 标签何时可用 |
|---|---|---|---|
| `base_train`，用途 `base_train` | `base_candidate.npz`，源自 `data/big_train_main.tfrecord` | 952 部底座电影的 683,455 行，1593 的 475 行全部排除 | 底座使用保留行的标签计算训练损失 |
| `meta_a`，用途 `meta_support` | `meta_a.npz`，源自 `data_with_hist/train_oneshot_a_w_ngb_hist.tfrecord` | 106 部伪新电影的 2120 行，包含 1593 的 20 行 | 后续 0.2 用 A 的标签适配属性生成的初值，再用 A 的正反馈用户校准 |
| `meta_b`，用途 `meta_query` | `meta_b.npz`，源自 `data_with_hist/train_oneshot_b_w_ngb_hist.tfrecord` | 同一批伪新电影的另外 2120 行，包含 1593 的另 20 行 | 后续 0.2 用适配后的向量对 B 评分，再用 B 的标签计算生成器的训练损失 |

三个入口都需传入 `holdout_path`。清单来自 `artifacts/holdouts/0.4/holdout.json`，只保存版本、算法、种子和电影 ID，交互行仍保存在原来的 NPZ。测试电影的三轮 warm-up 在 0.5 定义，完整的 `final_eval.npz` 留给四个测点评分。划分和底座预训练都可以在最终评估文件缺席时完成。[本机划分清单](../../artifacts/holdouts/0.4/holdout.json) · [用途映射](../../src/coldstart/data/schema.py) · [访问与行序测试](../../tests/test_item_holdout.py)

## 为什么还要数邻居

1593 的 10 个邻居中，`2096、957、1373、401、197、191` 属于底座组，有从自身交互学到的 ID 向量。另外 4 个邻居也在伪新组。0.4 保留了 `items.npz` 的原始邻居名单，另行记录每部电影可借用几个底座邻居。0.6 实现 GME 时，只在借用预训练 ID 向量的环节筛邻居。可用数为零时，生成器用目标电影自身属性生成初值。[物品元数据](../../artifacts/movielens/items.npz) · [本机邻居统计](../../artifacts/holdouts/0.4/neighbors.json)

实测 106 部伪新电影共 1060 个邻居位置，其中 105 个指向伪新组，每部至少还有 6 个底座邻居。1127 部测试电影的 11,270 个位置中，1195 个指向伪新组，每部至少还有 5 个底座邻居。本次固定划分中的每部目标电影都有可用邻居。原始选邻规则及邻居名单在上架时是否可得仍待核实。[统计口径与零邻居测试](../../tests/test_item_holdout.py) · [阶段 0 决策](../DECISIONS.md#04-物品划分与底座复用)

## 公共权重怎样训练和复用

底座用批量特征 `[B, 16]` 查共享 embedding 表，掩掉填充位、按槽池化，拼出 `[B, 80]`。MLP 给出 `[B]` 个 logits，结合 `[B]` 个二值标签计算 BCE。训练种子 `123` 控制权重初始化和样本打乱。Adam 以学习率 `0.001`、批量 128 完整遍历底座组一次，共更新 5340 步，最后一批 63 条。保存最后一步权重，选择过程只依赖预先设定的预算。[底座实现](../../src/coldstart/models/base_dnn.py) · [训练入口](../../scripts/train_base.py)

本机产物在 `runs/0.4-base/`。`weights.pt` 是后续各方法应加载并冻结的参数，`config.yaml` 和 `holdout.json` 保存运行时使用的配置和划分。实现提交 `0398184` 的运行记录包含划分摘要、实际行数、步数及损失。单种子训练过程按样本加权的平均 BCE 为 **0.549319**，最后一批的 logits 在新建模型重载权重后逐值相等。冷启动效果还要在后续任务按 0、20、30、40 条反馈分别评测。[本机运行记录](../../runs/0.4-base/metrics.json) · [复现命令](../plans/0.4-item-holdout.md#验收标准)

回看这次划分，可以先查自己的目标电影在哪一组，再核对它从哪一个入口进入模型。`test_holdout_views_match_source_rows` 用完整源文件逐行验证三个入口，`test_modeling_requires_verified_holdout` 验证缺失或篡改清单时拒绝读取。`test_real_base_epoch_and_checkpoint_reload` 则在训练前向里观察实际消费的样本，覆盖尾批、权重更新和重载。三处分别回答了名单怎样约束数据、调用者能否绕过约束、模型最终用到了哪些行。[数据测试](../../tests/test_item_holdout.py) · [训练测试](../../tests/test_train_base.py)
