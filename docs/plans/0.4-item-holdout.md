# 任务 0.4 · 物品级留出与共用底座预训练

**2026-11-29 已获批。** 本计划确定 9:1 物品划分、GME 邻居使用范围、数据访问接口和单轮预训练预算。实现分支为 `feat/0.4-item-holdout`。[决策记录](../DECISIONS.md#04-物品划分与底座复用) · [路线图](../../ROADMAP.md)

## 目标与现状

交付一份固定的电影 ID 清单、一份邻居覆盖统计，以及在真实底座组交互上训练的可重载权重。0.2 用这份清单取伪新电影的 support/query，0.6 的各方法加载同一份冻结权重，以便比较电影向量的生成与适配效果。

0.1 已验证 `base_candidate` 的 765,669 行与 `meta_a/b` 覆盖相同的 1058 部老电影，测试侧覆盖另 1127 部电影。元训练 A/B 各含每部老电影的 20 条交互。当前 `train_base.py` 只接收内部生成的合成样本。架构文档约定元训练 A/B 须经过留出筛选，当前 `MovieLensDataset` 却允许以 support/query 用途打开全量 A/B。0.4 会将这项约定落实到读取入口。[数据接口](../ARCHITECTURE.md#31-数据用途split) · [用途定义](../../src/coldstart/data/schema.py) · [0.1 核验记录](0.1-pytorch-port.md)

## 物品划分与数据接口

1. **固定电影名单。** 从候选集取去重、升序的电影 ID，核对原始 A/B 的电影集合均与之相等。拟用固定划分种子 `42` 和 NumPy `PCG64` 打乱这 1058 个 ID，前 106 部作伪新组，其余 952 部作底座组。用物品表全集减去老电影得到测试电影集合。划分只依赖 ID，独立于行序、交互标签、邻居覆盖及训练种子。
2. **保存可复用的划分。** 在 `artifacts/holdouts/0.4/` 写出 `holdout.json`，含格式版本、算法、划分种子和三个组各自排序后的 ID 清单。保留 0.1 的源 NPZ 与清单，读取时按电影筛行，无需额外复制三份交互文件。生成入口先在临时目录完成校验，再整体发布。同样输入可重复执行，已有目录内容冲突时报告差异。
3. **在建模入口校验。** 保留 `MovieLensDataset(root, split, purpose)` 的现有位置参数，增加关键字参数 `holdout_path`。真实 `base_train + BASE_TRAIN` 从 `base_candidate` 仅取底座电影。`meta_a + META_SUPPORT` 和 `meta_b + META_QUERY` 从各自源文件仅取伪新电影。这三种读法须验证清单的版本、种子与分组一致性、三组互斥与覆盖，以及源数据的电影 ID 归属，再按源行序筛选。原始候选集和原始 A/B 仍可用 `PARTITION` 完整读取。保留现有样本格式、特征校验和 `final_eval` 仅评分的限制。划分和预训练都无需打开最终评估文件。
4. **统计邻居覆盖。** 仅从 `items.npz` 取原始邻居 ID，在同一目录的 `neighbors.json` 分别报告 106 部伪新电影与 1127 部测试电影的覆盖情况。逐电影记录 10 个邻居位置中指向底座组的个数，按组记录可用数为 0 至 10 的电影数，以及指向伪新组的位置占比（分母为该组目标电影数 × 10）。这份统计供 0.6 解释邻居信息的覆盖范围。没有可用邻居时回退到自身属性，具体生成器由 0.6 实现。

## 预训练预算与权重选择

| 项目 | 拟采用的设置与依据 |
|---|---|
| 训练输入 | `configs/base_holdout.yaml` 指定 `data.split: base_train`、0.1 数据根目录 `data.root` 和 `data.holdout_path`。沿用当前 `BaseDNN`、BCEWithLogitsLoss 和确定性 CPU 路径。 |
| 固定预算 | 训练种子 `123`，Adam 学习率 `0.001`，batch size `128`，`epochs: 1`。种子控制初始化和训练行打乱。每轮无放回遍历全部底座行，保留尾批。实际训练步数为底座行数除以 128 后向上取整。0.1 合成冒烟继续使用原配置的 `steps`。 |
| 权重选择 | 预先指定保存完整一轮的最后一步。沿用旧底座有据可查的单轮预算，免去验证集选点，也避免使用伪新组、warm-up 或最终评分标签挑权重。这一轮用于提供各方法共享的起点。旧配置见 [config_dnn.py](../../config_dnn.py)。 |
| 运行产物 | `runs/0.4-base/` 保存 `weights.pt`、配置快照、划分清单副本和 `metrics.json`。记录可定位到训练代码的 git commit、训练种子、清单 SHA-256、实际行数、已训练样本数、更新步数、训练 BCE 和重载校验。登记单种子预训练记录，多种子冷启动效果比较归 0.6。 |

## 验收标准

| 测试或运行 | 通过条件 |
|---|---|
| `test_holdout_is_reproducible_and_label_independent` | 同种子重跑、打乱输入行序或翻转交互标签，得到同一组 ID。三组两两互斥，覆盖物品表中的全部电影。重复生成相同产物可成功，输出冲突及输入不合法时保全已有产物。 |
| `test_holdout_views_match_source_rows` | 从三个正式读取入口逐行对照源文件按目标组过滤的结果，特征、标签、行序和尾行全部一致。真实数据验收时三组恰为 952 / 106 / 1127 部，A/B 各 2120 行，每部伪新电影各有 20 行。测试组 ID 与测试侧 warm A/B 的电影 ID 相等。 |
| `test_modeling_requires_verified_holdout`、`test_holdout_does_not_open_final_eval` | 缺清单、分组错置或源电影集合不符时，三个建模入口均报错。最终集文件缺席时仍能划分并用小样本走完训练。保留原有 `test_train_rejects_ineligible_splits` 中对缺少合法划分的 `base_train` 的拒绝用例。 |
| `test_neighbor_coverage_counts_only_base_movies` | 用可手算的电影名单覆盖全有效、部分有效、零有效邻居。逐电影计数、两组的分母与汇总一致，原始邻居名单可逐项核对。 |
| `test_real_base_epoch_and_checkpoint_reload` | 用小型留出数据从正式入口训练，观测实际进入模型的电影 ID、样本数和尾批。仅底座组进入更新，每行恰好一次，权重发生变化，损失有限。清单摘要与运行记录一致，同一 CPU 样本重载前后 logits 逐值相等。 |
| 本机完整验收 | 全量 pytest 和合成冒烟通过。按以下命令生成正式划分并完成一个真实 epoch，核对实际样本数、步数、有限损失和重载记录，再登记本机产物。固定训练预算，无 AUC 门槛。 |


## 风险与面试要点

- 只删除元训练 A/B 中的交互行，底座仍可能从同一电影的其他交互学到它的 ID 向量。面试时可用一部伪新电影沿两条数据入口解释，为什么必须把它的全部交互从预训练中留出。
- 9:1 约束的是电影数。单部电影交互量不同，底座行数及邻居覆盖要等固定划分后实测。原始邻居在上架时是否可得仍待核实，覆盖统计只说明有多少邻居具备预训练 ID 向量。
- 同一份划分和同一份冻结权重分别控制数据差异与底座差异。单种子训练 BCE 和重载校验能验证本次交付，四个冷启动测点的效果由 0.7 定义指标、0.6 做多种子比较。
