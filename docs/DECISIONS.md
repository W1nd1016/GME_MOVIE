# 技术决策记录

## 2026-11-27 · 开发环境与阶段 0 评估协议

以下决定已由用户确认。[开发规则](../AGENTS.md) · [阶段 0 路线图](../ROADMAP.md)

| 事项 | 决定 | 备选方案与取舍理由 |
|---|---|---|
| 开发与训练环境 | 在当前 VS Code 连接的 WSL2 Ubuntu 上完成开发、测试、正式训练和评测，按单张 RTX 4090 预算设计。 | 原方案在 Mac 开发、另机训练，再回传结果。当前 WSL 可以统一执行并直接核对本机产物。 |
| 阶段 0 的到达顺序 | 使用仓库内已加工的 MovieLens-1M。交互缺少时间戳，用互斥批次模拟反馈到达，后一批在前一批用完后才开放。 | 重建真实时间线需要额外取得带时间戳的原始数据并恢复映射。现有数据足以检验各测点的信息可见性。阶段 2 将在带时间戳的主实验数据上按实际事件时间回放。 |
| 三轮 warm-up 与评估集 | 每部新电影先开放测试侧 A 的 20 条，再依次开放测试侧 B 的两组各 10 条。B 按电影固定划分，与标签无关，所有方法和训练种子共用。三批与完整的 `test_test_w_ngb_hist.tfrecord` 按（用户，电影）两两互斥。四个测点在该集合上评估累计 0、20、30、40 条交互的效果。 | 旧 A/B 方案只能观察两轮。拆分 B 可增加一个观测点，同时保留全部 1127 部新电影、原有的 20/40 条测点和 123,787 条最终评估样本。 |
| 历史反馈的可见范围 | cold 时目标电影的 `hist` 为空。每轮更新后仅从该电影累计已开放的正反馈重建 `hist`。元训练若采用 A→B，只用 support A 的正反馈校准适配后的 embedding，再在 query B 评分。最终评估数据仅用于评分，标签及其派生信息不得用于生成或更新 embedding、训练或早停。 | 直接使用旧文件附带的 `hist` 会把当前或最终评估批次的正反馈用户提前暴露给模型。具体证据见[旧代码审查](../CODE_REVIEW.md)。 |

## 2026-11-28 · 阶段 0 泄漏修复的验收

取消用旧 `hist` 重跑以量化指标偏差的对照实验。该实验只能估计旧协议对指标的影响。新协议通过 0.2、0.3 的测试验证历史反馈的可见范围，0.6 的基线按新协议比较。[阶段 0 交付物](../ROADMAP.md#13-交付物)
