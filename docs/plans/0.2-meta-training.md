# 任务 0.2 · 修复元训练 A → B 的标签泄漏

2026-11-29 已获批，实现分支为 `feat/0.2-meta-training`。

## 目标与探索结果

在一部伪新电影上，先用上架属性生成冷启动向量，用 support A 的 20 条反馈适配，再用 A 中的正反馈用户校准，最后用冻结底座对 query B 的 20 条交互评分。要分别证明两件事：改变 B 标签时，本次评分用的电影向量和 logits 保持相同；评分完成后，训练电影的 B 损失可以沿适配步骤更新共享生成器。[任务进度](../PROGRESS.md) · [已确认的 0.2 决策](../DECISIONS.md#02-元训练电影数量与验证)

- 已从 0.4 的建模入口核对数据。A、B 各有 2120 行，覆盖相同的 106 部伪新电影；每部每批各 20 个不同用户，两批的（用户，电影）交集为空。A 每部有 1–18 位正反馈用户，因此还需要合成全负的 A 样例检验空历史。[数据读取](../../src/coldstart/data/movielens.py) · [既有划分测试](../../tests/test_item_holdout.py)
- 已核对 `runs/0.4-base/` 的权重存在，随权重保存的电影清单与当前 `artifacts/holdouts/0.4/holdout.json` 摘要一致。当前底座会查电影 ID 表，只有 `forward(features)` 这一条评分路径。架构文档将外部电影向量评分与可见历史列为待实现，与代码一致。[底座实现](../../src/coldstart/models/base_dnn.py) · [架构文档](../ARCHITECTURE.md)
- 旧 TF1 在 A 评分前就把含 B 正反馈用户的 `hist` 放进电影向量。0.1 已在转换时丢弃该字段，0.4 已按电影隔离底座训练。0.2 需要在模型的正常训练入口验证信息出现的时机。测试电影的逐轮更新属于 0.3，四测点指标与正式基线分别属于 0.7、0.6。[旧代码审查 P0-1](../../CODE_REVIEW.md) · [路线图](../../ROADMAP.md)

## 拟定的数据流与模型

| 步骤 | 可见输入与拟定操作 |
|---|---|
| 取得一部电影的任务 | 通过现有 `meta_a / meta_support` 和 `meta_b / meta_query` 读取经留出的样本，用电影 ID 配对，检查电影覆盖、每批 20 条、批内用户唯一且 A/B 互斥。电影 ID 用于分组及查物品表。仅将该片 year、title、genres 三个属性槽交给生成器。 |
| 生成初值、给 A 评分 | 用冻结的共享表嵌入属性，对 title、genres 各自掩掉 ID 0 后按槽求和，与 year 拼成 30 维向量。单个线性层输出该电影的 10 维初值 `r`。同一部电影的全部 A 交互共用一个 `r`，先产出 A logits，再用 A 标签计算平均二元交叉熵。 |
| A 上做一步适配 | 每部电影独立计算 `r′ = r − η ∇r loss_A`，拟固定 `η = 0.1`。每部的梯度已对自己的 20 条交互取平均，同时处理多部时，对各电影的平均损失求和再对各自的临时向量求导。这样 4 部合批与 1 部尾批的单片步长一致。元训练保留这一步的求导图，使用完整的一步 MAML 梯度。 |
| 用 A 的正反馈校准 | 按片从已开放的 A 中取正反馈用户 ID，求其冻结用户向量的均值 `h_A`，分母为实际人数。用无偏置线性层计算 `r″ = r′ + W_h h_A`。空历史取零向量，此时校准结果恰等于 `r′`，全负 A 的适配梯度依然保留。历史构造可供 0.3 传入累计已开放的反馈。 |
| 给 B 评分、更新或验证 | 用同一个 `r″` 给该片全部 B 交互评分，评分接口只收交互特征和电影向量。拿到 logits 后才按 B 标签计算 query logloss。训练时按批内电影平均该损失，用 Adam 更新生成器和校准层，拟定外层学习率为 0.001。验证时仅对每部电影的临时向量求 A 梯度，B 只计损失。 |

底座拟扩展为 `forward(features, *, movie_embedding=None) -> logits`。外部向量形状为 `[交互数, embedding_dim]`，按槽名替换 movie 槽，与原路径共用池化规则和 MLP。底座参数全程冻结，对输入电影向量保留梯度。已有调用、扩展槽位测试及 0.4 权重均可沿用。[现有评分测试](../../tests/test_base_dnn.py)

审查文档举过 A/B 混合外层损失的例子。本次选择让 A 损失负责适配、B 损失单独训练共享模块，方便检验“在 A 上适配后能否预测 B”。使用实际正反馈均值和线性残差做最小校准，保留适配后的向量，也允许校准分量取负。用实测的适配改变量、生成器梯度和元验证损失检查步长及优化效果。[旧实现](../../warm_up_dnn_base.py) · [旧代码审查](../../CODE_REVIEW.md)

## 训练划分、对照与预算

1. 对 106 个伪新电影 ID 排序，用独立的固定划分种子 `2026` 做一次 PCG64 置换。前 21 部为元验证，其余 85 部为元训练，训练名单依置换顺序取前 25、50、85 部得到嵌套子集。所有方法及训练种子共用这些名单，每片的 A/B 始终同组。运行目录保存实际电影 ID。
2. 拟用训练种子 `123、456、789`，每个种子跑四组：属性生成器分别用 25、50、85 部电影，共享初值对照用 85 部，共 12 次。对照把属性线性层换成一个可学习的 10 维向量，并为每部电影产生独立的临时适配向量。两种方法的冷初值与校准增量均从零开始（属性层和校准层零初始化），用同一底座、同一适配公式与同结构校准层。同种子的两个 85 部组使用相同的电影批次顺序。
3. 85 部组每轮打乱后遍历一次，批量为 4，保留最后 1 部，每轮共 22 步。电影数实验也按每 22 步共 85 个电影任务安排：在各自子集内每轮取一个随机排列，循环使用至取满 85 个位置，按相同的批大小切分。这样三个规模都跑满 440 步、1700 个电影任务；记录实际更新步数与部次，区分增加独立电影和重复看同一电影的效应。
4. 在第 22、110、220、440 步用**同一检查点**重新计算本组全部训练电影、固定 21 部验证电影的 B logloss，对应 85 部组的第 1、5、10、20 轮。记录每个种子的结果及跨种子的均值 ± 样本标准差。预算诊断比较属性组与共享初值组的曲线；电影数量的主比较统一取第 440 步。另按元验证损失最低的检查点选择供后续复用的权重，并列取最早；这样也能在训练继续改善而验证转差时选取较早的模型。
5. 记录 A 适配前后的向量距离及 B 到生成器的梯度范数。训练损失难以优于共享初值时，先用这些观测定位梯度链或优化问题。若第 20 轮两条曲线仍在下降，记录延长预算的依据。若 25 → 50 → 85 部呈持续改善，按既有决定另议 8:2 和重训底座。任务验收依据协议、梯度检查和实际完成的诊断，模型优劣按真实结果报告。

## 面试可讲点

- **为什么 A/B 样本互斥仍会泄漏？** 只要生成电影向量的历史含有 B 的正反馈用户，预测就可能提前用到答案。固定参数、单独翻转 B 标签，可以直接检查这条路径。
- **冻结底座为什么还能训练生成器？** 底座对电影输入向量的导数仍能计算。外层 B 损失经过冻结的评分函数、校准和 A 的一步适配传回生成器，全程无需更新底座权重。
- **怎样区分训练不够和电影太少？** 固定 85 部比较各预算的训练、验证曲线，再固定 440 次更新、电影任务总数和同一批验证电影，比较不同数量独立训练电影的结果。
